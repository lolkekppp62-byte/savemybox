# Савеми Бокс

Независимый Android-клиент на libbox sing-box 1.14.4 с русским интерфейсом. Пакет `com.savemy.singboxfork`. Это новый интерфейс и адаптер libbox по архитектуре SFA, а не копия полного репозитория SFA. Не связан с SagerNet.

**Статус:** исходный проект и сценарий сборки подготовлены. APK в текущей среде НЕ собран: установлена Java 8, нет Android SDK и Go. Успешная полная компиляция Android, работа JNI, VPN и внешний вид на телефоне пока не подтверждены. Проверка синтаксиса и JVM-тесты не заменяют эти проверки.

## Архитектура

Один модуль `app`, внутри разделены ответственности:

- `data/Models.kt` — узлы, BL/WL, фильтры, настройки и интервалы.
- `data/Importer.kt` — импорт ссылок и самостоятельного outbound JSON.
- `data/Repository.kt` — атомарное сохранение AES-GCM с Android Keystore, StateFlow. Резервное копирование приложением отключено. При повреждении файла запись блокируется, исходный файл не затирается.
- `core/ConfigFactory.kt` — динамическая конфигурация DNS, TUN, прокси, selector, исключения пакетов, MTU и TUIC.
- `core/Engine.kt` — жизненный цикл CommandServer, проверки узлов и переключение.
- `core/AndroidPlatform.kt` — платформенный API libbox: защита сокетов, интерфейсы, монитор лучшей физической сети, определение владельца соединения на Android 10+.
- `core/LocalApi.kt` — запросы к локальному Clash API, случайный секрет, только loopback. Закрытие ожидающих сокетов при отключении.
- `vpn/BoxVpnService.kt` — Android VpnService, TUN, foreground-уведомление и системное разрешение VPN.
- `ui/BoxScreen.kt`, `SettingsScreen.kt`, `Theme.kt` — Compose Material 3, три вкладки, дополнительные экраны.
- `work/RefreshWorker.kt` — периодическая диагностика через WorkManager.
- `core/Journal.kt` — ограниченный журнал событий без импортированных ссылок/ключей.
- `tools/` — сборка, JVM-проверки, синтаксический анализ и упаковка исходников.

Технологии: Kotlin 2.1.21, Compose BOM 2025.05.01, Material 3, Coroutines, kotlinx.serialization, WorkManager, Android Keystore, libbox через gomobile. Min SDK 26 (Android 8), compile/target SDK 36. AGP 8.10.1, Gradle 8.11.1.

## Что реализовано в исходниках

### Главная и узлы

- Большая кнопка «Подключить» / «Отключить», состояния отключено / подключение / включён VPN / ошибка. Отключение доступно во время диагностики.
- Активный узел, последняя задержка, сообщения о переключениях.
- «Найти рабочие узлы» на двух вкладках; три HTTPS-пробы через каждый отфильтрованный outbound, до восьми узлов одновременно, результаты только для успешных узлов.
- Задержка — медиана успешных URL-проб, **не ICMP ping**. «Потери запросов» — доля неудачных проб из трёх, **не процент потерянных IP-пакетов**. Одна успешная проба считается доступностью.
- Цель проверки: `https://www.gstatic.com/generate_204`. Недоступность этой цели способна дать ложный отрицательный результат; успешный тест не гарантирует доступность всех сайтов или UDP.
- Ссылки `vless://`, `vmess://` (Base64 JSON), `trojan://`, `ss://`, `hysteria2://` / `hy2://`, `tuic://`; TCP, WebSocket, gRPC, TLS, Reality в поддерживаемых вариантах.
- JSON: отдельный outbound или массив. Поддерживаемые типы: vless, vmess, trojan, shadowsocks, hysteria2, tuic, socks, http, hysteria, anytls. Это не импорт целой конфигурации или подписки. Узел должен быть самостоятельным, без detour/domain_resolver на другие записи.
- Неизвестные URL-параметры отклоняются, подробные протокольные настройки можно передать через JSON. Для JSON окончательная проверка схемы остаётся за ядром; неподдерживаемое поле способно помешать запуску всей конфигурации. Такой узел нужно удалить/исправить. Одновременная диагностика изолирует сетевые ошибки, но не ошибки построения общей конфигурации.
- Проверки UUID, порта и обязательных полей, русские сообщения без исходного секрета; небезопасные TLS-параметры в ссылках отклоняются. JSON считается явной экспертной конфигурацией и может содержать `insecure`.
- BL/WL назначаются при импорте или после него. Все / BL / WL — общий фильтр диагностики и допустимых кандидатов. BL никогда не выбирается для подключения; фильтр BL позволяет только диагностику. При изменении фильтра активная конфигурация обновляется; BL без допустимых кандидатов останавливает VPN с ошибкой, а не включает direct.
- Карточка узла: протокол, статус, время последней проверки, задержка, «Обновить», выбор, отметка и удаление с подтверждением.

### Настройки

- «Как в системе» по умолчанию, светлая, тёмная, Хэллоуин, Новый год. У новогодней темы полупрозрачный снег без перехвата нажатий. При системном отключении анимаций снег не запускается. Хэллоуин использует тёмный фон и янтарный акцент.
- Пять акцентов применяются без перезапуска; изменения оформления не перезапускают VPN.
- «Российские сервисы»: редактируемый стартовый список пакетов VK, MAX, Госуслуг, Яндекса, Ozon, Wildberries, Сбера, Т-Банка, Mail.ru. Названия пакетов могут отличаться у региональных версий; список не определяет страну автоматически и не является исчерпывающим.
- «Обход VPN»: поиск по установленным приложениям, флажки и счётчик. Исключения применяются через `VpnService.Builder.addDisallowedApplication` и `exclude_package`. На Android 10+ также создаётся `package_name` bypass-правило ядра; на Android 8–9 работает исключение из TUN.
- Smart Routing: цикл с паузой 30 секунд после завершения предыдущей проверки, три неудачные пробы активного узла, затем выбор самого быстрого проверенного кандидата вне BL с учётом фильтра. Видимое сообщение и уведомление. При отсутствии кандидатов VPN не переключается напрямую; существующие соединения при смене узла могут оборваться.
- Интервал по умолчанию 60 минут; 30 минут, 1/2/5/8/10/12/24 часа; свои минуты/часы/дни. Диапазон **15 минут — 30 дней** обусловлен ограничением периодического WorkManager. Android может отложить работу при Doze/энергосбережении. Это обновление статуса узлов, не загрузка подписок.
- MTU 8500/1500/1480/1400/1280; ручное значение передаётся TUN. Большой MTU не гарантированно подходит сети.
- **Adaptive MTU — приближение, не PMTU Discovery:** минимальный MTU доступных физических сетей минус 100, ограничение 1280–1500 и выбранным максимумом. Пересчёт при запуске/переподключении; активного DF/ICMP probing и автоматического повторного подбора при каждом изменении пути нет. Ближайшая безопасная альтернатива — ручные 1280/1400.
- **Packet Recovery:** только TUIC, `udp_relay_mode=quic`, надёжная передача UDP в потоках QUIC. Исключается конфликтующий `udp_over_stream`. Это не FEC и не универсальное восстановление пакетов; возможна задержка из-за ожидания повторной передачи. Для других протоколов опция не применяется; UI объясняет ограничение.
- Изменения сетевых настроек сохраняются и перезагружают конфигурацию; возможен краткий разрыв. Темы и расписание не вызывают перезагрузку туннеля.
- Журнал соединения и проверок — отдельный экран, до 300 событий. Внутренний журнал ядра хранится отдельно в закрытом каталоге приложения и может содержать сетевые адреса; не публикуйте его без проверки.

## Сборка на Windows одной командой

Предварительно установите самостоятельно (скрипт не устанавливает системные среды):

1. **JDK 17**, задайте `JAVA_HOME` на корень JDK, не `bin`.
2. **Go 1.25.5 или новее**, доступный как `go` в PATH. Версия требуется закреплённым go.mod ядра. Новейшие зависимости могут вызвать штатную загрузку Go toolchain; нужен интернет.
3. **Python 3.11+** (в этой среде уже есть).
4. **Android SDK** через Android Studio / SDK Manager: Android SDK Platform 36, Build-Tools 35.0.0, Platform-Tools, Android SDK Command-line Tools, **NDK 28.2.13676358**. Примите лицензии SDK Manager.
5. Задайте `ANDROID_HOME` на каталог SDK. `ANDROID_NDK_HOME` сценарий выставит сам. Нужен интернет к Maven, Google Maven, GitHub, Go proxy и Gradle.

Пример переменных для текущего окна cmd (замените путь JDK своим):

```bat
set "JAVA_HOME=C:\Program Files\Eclipse Adoptium\jdk-17"
set "ANDROID_HOME=%LOCALAPPDATA%\Android\Sdk"
cd /d "C:\Users\Ryzen\OneDrive\Документы\щаровкин\singbox-fork"
build.cmd
```

`build.cmd` выполняет `python tools/build.py`: проверяет окружение, получает Gradle с проверкой SHA-256, скачивает исходники ядра по commit `c005f35300ce76427dc285481ec5695f5b179cd2`, собирает libbox через закреплённый gomobile v0.1.12 и запускает тесты, lint и debug APK. AAR проверяется по записи commit/параметров/хеша, несовпадающий пересобирается. Ядро собирается без Naive, SSH и Tailscale; их интерфейсные методы не используются.

Результат успешной сборки:

```text
app\build\outputs\apk\debug\app-debug.apk
```

После подготовки libbox прямые команды Gradle:

```bat
.tools\gradle-8.11.1\bin\gradle.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Предварительная проверка: `python tools/build.py --check`.
Если NDK/Go-инструменты отказываются работать из пути OneDrive с кириллицей, скопируйте **весь** каталог в `C:\dev\SavemyBox` и повторите; не переносите только отдельные исходники.

## Установка APK

Включите отладку USB и подтвердите доверие компьютеру на телефоне:

```bat
build.cmd --install
```

Либо после успешной сборки:

```bat
"%ANDROID_HOME%\platform-tools\adb.exe" install -r app\build\outputs\apk\debug\app-debug.apk
```

Можно перенести APK на телефон и открыть его, разрешив установку из выбранного источника. При первом подключении подтвердите системное разрешение VPN. Разрешение уведомлений запрашивается на Android 13+. APK debug подписан отладочным ключом и не предназначен для магазина.

## Выполненные и невыполненные проверки

- `python tools/test_core.py`: **OK (16 tests)**; настоящая компиляция Kotlin/JVM для импорта, моделей, генератора конфигурации и локального API. Тесты HTTP используют реальный loopback-сокет, не VPN.
- Тот же сценарий: **Kotlin syntax: OK (17 files)**. Парсер Kotlin проверяет все исходники app/src; это не проверка Android/Compose типов и JNI.
- `python -m py_compile tools/build.py tools/test_core.py`: прошёл.
- Проверка окружения остановлена на Java 8 вместо JDK 17. **assembleDebug, Android lint, libbox AAR, установка APK и проверка VPN не выполнены.**
- Два исследователя проверили API ядра и исходники приложения. Полноценный автоматический проверяющий агент в среде недоступен. Найденные проблемы остановки/перезапуска исправлены; гипотеза о лишней скобке опровергнута текущим Kotlin-парсером.

После сборки требуется приёмка на Android 8 и современном Android: разрешение VPN и уведомлений, все шесть протоколов на реальных тестовых узлах, DNS/IPv6, исключённые приложения, смена Wi-Fi/мобильной сети, отказ узла, отзыв VPN, отключение во время проверки, перезапуск процесса, Doze, темы и крупный шрифт. Ни браузерная проверка, ни JVM-тесты не проверяют нативный Android UI.

## Безопасность и ограничения распространения

Тестовые серверы, чужие учётные данные и платные сервисы не добавлены. После установки добавьте собственный узел. При выключении VPN обычная сеть Android вновь доступна: это **не системный kill switch**. Для блокировки утечек настройте в Android «Всегда включённая VPN» и «Блокировать соединения без VPN», учитывая конфликт с желаемым обходом отдельных приложений.

Разрешения: интернет, сеть и её запрос, уведомления, foreground systemExempted, BIND_VPN_SERVICE на экспортированной службе. QUERY_ALL_PACKAGES нужен для экрана всех приложений; публикация в Google Play требует отдельного обоснования и проверки политики. Не выполнялась публикация или настройка release-подписи.
