# 0.3.1

## Изменения в исходниках
- Полная ручная проверка охватывает все узлы. Лучший разрешённый узел подтверждается через ядро; после проверки запрашивается разрешение VPN и выполняется подключение. TCP без ядра не запускает VPN.
- На главной: раскрывающаяся панель TCP / HTTP HEAD / HTTP GET / ICMP, профиль «Быстрая / Точная», адрес выбранного сервиса, свой HTTPS URL и таймаут.
- На главной: раскрывающиеся строки узлов, редактирование названия, ссылки/JSON, wl/bl/обычный и папки; удаление с подтверждением.
- Папки и совмещение 2–25 узлов в группу с отдельной проверкой. Это группировка, а не цепочка прокси и не суммирование скоростей.
- Исправлена гонка загрузки настроек при автозапуске после перезагрузки; запуск службы проверяет разрешение и сообщает безопасную причину отказа.
- Битые outbound не остаются в selector.
- Бета-канал теперь видит и prerelease-выпуски, а не только legacy 0.0.*. Стабильный канал предварительные выпуски не получает. Сама 0.3.1 публикуется обычным выпуском, чтобы её увидела установленная 0.3.0.

## Совместимость и доставка
Версия в Gradle: 0.3.1, versionCode 6. Android 8+ (API 26), только arm64-v8a. Подпись сохранена без замены ключа: менять ключ нельзя без проверки совместимости с установленным APK. Сертификаты установленного и нового APK ещё не сверены. Код 6 необходимо сопоставить со всеми ранее распространёнными APK перед публикацией.

Установленная 0.3.0 не увидит 0.3.1, если выпуск помечен prerelease, поэтому 0.3.1 публикуется обычным выпуском. Старый APK обновляется только при совпадении подписи и versionCode; при расхождении установка поверх не пройдёт. Не удаляйте приложение ради установки: зашифрованные профили могут быть потеряны.

GitHub Actions создаёт выпуск с названием «0.3.1» без перезаписи существующего: повторная сборка той же версии завершится ошибкой, нужно поднять versionName/versionCode. Git-инструмент этой сессии работает из родительского каталога, где репозитория нет; фактический репозиторий находится во вложенном singbox-fork. Новый репозиторий в родительском каталоге создавать не следует.

## Проверки
- `py -3.11 tools/test_core.py`: 107 тестов, Kotlin syntax OK (47 files). Это не Android type checking.
- `py -3.11 tools/build.py --check`: остановлен — нужна JDK 17, найдена Java 1.8.0_481. APK не собран.
- Не проверены: компиляция Android/Compose, JNI, установка поверх предыдущей версии, VPN/TUN, внешний вид и взаимодействия на устройстве, Play Protect, доставка опубликованного обновления.
- Разведчик проверил цепочку Activity → foreground service → Engine → libbox → TUN. Безусловной ошибки декларации VPN-службы не обнаружено. Изменения исправляют найденные дефекты, но не устанавливают причину отказа конкретного телефона.

## Проверка на устройстве перед выпуском
1. Собрать release через tools/build.py в окружении JDK 17, Android SDK, NDK и Go по проверкам этого сценария. Выполнить Android unit tests и lint; сверить APK versionCode, ABI и сертификат с установленной версией.
2. Установить поверх 0.3.0 без удаления данных. Проверить сохранность узлов/настроек, отказ и выдачу системного разрешения VPN, запуск/отключение, повторный запуск службы и отзыв разрешения.
3. Полная проверка с рабочими и нерабочими узлами, BL и фильтрами: выбирается подтверждённый разрешённый узел, запрашивается VPN; при отказе ядра/TCP-only/нуле результатов подключения нет. Проверка одного узла и расписание не включают VPN сами.
4. Проверить все методы, профили и цели URL, свой невалидный URL и таймаут. Настройки сохраняются после перезапуска.
5. Добавить, переименовать, отредактировать и удалить узел с отменой/подтверждением; проверить папку и группу 2/25/26 узлов, перемещение и сохранность после перезапуска.
6. Зафиксировать точный текст предупреждения Play Protect и SHA-256 APK. Не отключать защиту и не обещать устранение ложного срабатывания по исходникам.
7. После публикации проверить Releases API, prerelease=true, скачивание APK, подпись и обновление из приложения предварительного канала. Старую 0.3.0 проверять отдельно с учётом указанного ограничения доставки.
